# MewCode Phase3 Spec — Agent Loop

## 背景

Phase2 已交付工具系统（六工具 + 注册中心 + 单轮工具循环），但模型一步一停，用户得一直催。本阶段给 MewCode 装上 Agent Loop：模型自主循环——先想、调工具、看结果、边做边调整，直到任务完成，从被动应答变成自主干活的 Agent。

真机环境：DeepSeek V4 Flash（OpenAI 协议）。已确认其支持工具调用（P2 真机验证通过）。

## 目标

- ReAct 循环：调 LLM → 执行工具 → 结果回写 → 再调 LLM……直到停止条件触发
- Agent 核心与界面通过异步事件流彻底解耦
- Plan Mode：/plan 计划（只读工具）→ /do 执行（全工具）
- run_command 转为自主执行（P2 的确认机制移除，权限系统留后续章节）

## 功能需求

- F1: ReAct 循环 —— 迭代不再限两轮：每轮 LLM 生成（流式）→ 若含工具调用则执行 → 结果回写历史 → 下一轮；若不含工具调用则完成
- F2: 停止条件（五类）—— ① 模型本轮无工具调用（正常完成）② 迭代达到上限（默认 15 步）③ 用户取消（Ctrl+C）④ 连续 2 次调用未知工具 ⑤ 流错误（网络/API/解析）
- F3: 异步事件流 —— Agent 核心对外发事件：text（增量）、tool_call（含参数）、tool_result（含成败）、token_usage（每轮用量）、progress（步数/状态）、done（含停止原因）；UI 只消费事件流，与 Agent 无直接耦合
- F4: 流式收集器双路 —— 同一轮 LLM 流：一路实时推 text 事件给 UI，一路攒完整响应（含 tool_calls 全文）供循环判断
- F5: 多工具调用分批 —— 一次 API 响应含多个 tool_calls 时：无副作用工具（read_file/find_files/grep_code）并发执行，有副作用工具（write_file/edit_file/run_command）串行执行；同一批内先并发读、再串行写，全部结果按原顺序回写
- F6: Plan Mode —— TUI 输入 `/plan` 进入计划模式：请求只带读类工具（read_file/find_files/grep_code），模型产出计划；输入 `/do` 切回全工具执行模式，计划文本作为上下文注入；模式切换时界面明确提示当前模式
- F7: 进度与用量展示 —— UI 显示每轮步数（如 `[2/15]`）、工具调用与结果行、累计 token 用量；循环结束显示停止原因

## 非功能需求

- N1: 停止即摘要 —— 循环结束显示：步数、停止原因、累计 token
- N2: 资源不泄漏 —— 每轮 streamChat 的响应流正确读完/关闭；取消时中断当前流并释放
- N3: 兼容纯对话 —— 模型无工具调用时单轮即完成，行为与 Phase1/2 一致
- N4: 自主执行安全底线 —— run_command 无确认直接执行（用户已决策）；工具结果仍 8KB 截断防上下文爆炸

## 不做的事

- 权限系统（目录白名单/命令黑名单）——下一章
- 上下文压缩/窗口截断 —— 后续章节
- 交互式确认（run_command 确认已移除）
- 工具执行失败自动重试策略
- 会话持久化与恢复

## 验收标准

- AC1: 多步任务自主完成 —— 真机提问「创建 hello.txt 写入『你好 MewCode』再读回来」→ 一次提问内模型自主完成写入+读取，UI 显示多轮工具调用与结果
- AC2: 迭代上限 —— fake provider 每轮都调工具 → 15 轮后停止，提示「达到迭代上限」
- AC3: 用户取消 —— 循环中 Ctrl+C → 干净停止，无残留进程/流
- AC4: 未知工具 —— 连续 2 次调用未知工具 → 停止并提示
- AC5: 流错误 —— 模拟网络中断 → 停止并提示错误
- AC6: 多工具分批 —— fake 响应同批返回 2 个读类调用 → 并发执行（时间重叠）；1 读 + 1 写 → 写发生在读完成之后
- AC7: Plan Mode —— fake 请求断言：/plan 模式请求 tools 仅含 3 个读类工具；/do 模式含全部 6 个
- AC8: 进度显示 —— UI 出现步数、累计 token、停止原因
- AC9: 真机冒烟（前置，不等验收）—— 开发 T0 即用真实 key 验证「多轮工具调用自主循环」链路可行，确认模型在循环中的真实行为
