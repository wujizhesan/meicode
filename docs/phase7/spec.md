# MewCode Phase7 Spec — 上下文管理

## 背景

P1-P6 已交付完整 Agent（工具/循环/权限/MCP）。长时间干活时工具结果与历史累积会撑爆上下文窗口。本阶段装两层压缩：轻量预防（工具结果存盘）+ 重量兜底（LLM 结构化摘要），保证长会话不因上下文溢出瘫痪。token 用近似估算（锚定 API usage + 增量字符估算），不做精确 tokenizer。

## 目标

- 工具结果大头走存盘，用户消息原文保留不摘要
- 历史逼近窗口时 LLM 摘要早期内容，近期原文保留
- 手动触发 + 失败熔断，防死循环

## 功能需求

- F1: 工具结果存盘（轻量预防）—— 单条工具结果 >4KB 时存盘到 `<cwd>/.mewcode/artifacts/`（时间戳命名），tool 消息内容替换为「[已存盘] 预览（前 200 字符）…完整内容: <相对路径>」；单条消息（同批多个工具结果）合计 >8KB 时挑大的依次存盘直至合计达标；8KB 截断机制保留作为存盘后的最终防线
- F2: LLM 结构化摘要（重量兜底）—— 整体历史估算逼近窗口上限时（自动触发余量 13K、手动 3K）调 LLM 非流式生成摘要；**较早消息摘要化、近期原文保留**（从尾部按 token 往回数：保留约 1 万 token 或至少 5 条消息，取二者较大）
- F3: 摘要 Prompt —— 明确禁止模型调用任何工具；要求先写分析草稿再写正式摘要（草稿仅内部使用，用完丢弃）；摘要按固定部分组织：任务目标 / 已完成事项 / 进行中事项 / 关键决策 / 文件与代码状态
- F4: 边界消息 —— 压缩完成后插入一条边界消息：「部分早期对话已摘要。如需文件/代码细节，请重新调用工具读取，不要凭摘要推测内容」；该消息不参与后续摘要
- F5: 手动触发与熔断 —— 用户输入 `/compact` 手动压缩（余量收窄到 3K）；摘要连续失败 3 次熔断：本次会话停止自动摘要并提示用户，手动 /compact 仍可用
- F6: 近似估算 —— 每轮记录 API usage 的 input tokens（锚点），新消息增量按 `字符数 / 4` 估算；首轮无锚点时按字符估算全量
- F7: 触发时机 —— 每次 API 请求前：先跑轻量预防（F1，管单条消息），再检查重量兜底（F2，管累积历史）；**用户 role 消息永不摘要**（原文保留）

## 非功能需求

- N1: 压缩不中断当前轮次（请求前同步完成压缩再发请求）
- N2: 存盘文件为 utf8 文本，可读可删
- N3: 摘要请求不进对话历史、不算轮次、不影响进度显示

## 不做的事

- 精确 tokenizer（tiktoken 等）
- 摘要策略的机器学习优化
- 向量检索/语义记忆
- 存盘文件自动清理策略

## 验收标准

- AC1: 4KB 存盘 —— fake 工具返回 5KB 结果 → tool 消息含「[已存盘]」+ 预览 + 路径；artifacts 文件内容完整
- AC2: 合计超限 —— 同批多个工具结果合计 >8KB → 大的先存盘
- AC3: 摘要触发 —— 估算逼近窗口（可配置小窗口便于测试）→ 早期消息被摘要替换
- AC4: 近期保留 —— 尾部 1 万 token / 至少 5 条消息为原文
- AC5: 摘要请求无工具 —— fake provider 捕获摘要请求：无 tools 参数
- AC6: 边界消息 —— 压缩后历史出现边界消息
- AC7: 手动触发 —— /compact 立即压缩（余量 3K）
- AC8: 熔断 —— 摘要连续失败 3 次 → 停止自动摘要并提示；/compact 仍可用
- AC9: 用户消息保留 —— 摘要后用户 role 消息仍原文存在
- AC10: 回归 —— 全部现有测试绿

## 触发时机汇总

```
每次 API 请求前:
  ① 轻量预防（F1）: 新产生的工具结果 >4KB → 存盘
  ② 重量兜底（F2）: 估算总量 > 窗口上限 - 余量
     自动触发余量 13K | /compact 手动余量 3K
  ③ 摘要失败计数 ≥3 → 熔断（会话内不再自动摘要）
```
