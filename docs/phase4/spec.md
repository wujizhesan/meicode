# MewCode Phase4 Spec — 系统提示工程

## 背景

Phase3 的 system prompt 是单块拼接文本（工具规则 + 模式命令说明已变长）。本阶段重构为结构化模块系统：稳定指令走缓存通道省钱省时，环境与动态指令走系统级补充消息注入，让 MewCode 从「能干活」变成「干得好」。

真机环境：DeepSeek V4 Flash。已知：`stream_options.include_usage` 兼容（P3-T0 验证）；DeepSeek 支持自动 context caching，usage 字段含缓存统计（字段名需真机确认）。

## 目标

- 全局指令按职责拆成模块，按优先级拼装，可插拔
- 稳定内容（指令+工具描述）与变化内容（环境/历史）分流，稳定前缀逐字节一致以命中缓存
- 双重强化关键规则（工具描述 + 系统提示）
- 独立 system 消息注入补充指令（不污染缓存前缀、不进对话历史、不被当用户输入）
- 会话级开关指令按轮次注入（首轮全量、每 3 轮全量、其余精简）
- 解析缓存命中字段验证策略生效 + 人工场景对比定性评估

## 功能需求

- F1: 模块化系统提示 —— 七个固定模块按优先级：身份 → 系统约束 → 任务模式 → 动作执行 → 工具使用 → 语气风格 → 文本输出，最后接环境信息模块；可选模块位（自定义指令 / Skill / 长期记忆）预留但本阶段不实现；模块间空行分隔，整体按优先级拼装，新增模块只改模块列表
- F2: 稳定/变化分离 —— 稳定模块（身份/约束/模式/动作/工具/语气/输出）拼成单一 system 消息（缓存前缀）；环境信息（当前目录、日期、工作区状态）拼成独立 system 补充消息追加在末尾；对话历史走消息通道
- F3: 双重强化 —— 关键规则（「优先用专用工具」「编辑前必先读」「工具失败调整重试」）同时在对应工具 description 与系统提示模块中出现，提高遵守率
- F4: 补充指令注入 —— 运行时动态指令（环境信息、会话级开关）以独立 `role:'system'` 消息注入，位于主 system 消息之后、历史之前；不进入对话历史对象；与用户消息天然区分
- F5: 轮次注入 —— 会话级开关指令（规划模式等）按轮次注入：第 1 轮全量、此后每 3 轮全量一次、其余轮次只注入精简版（关键句）；模式切换时立即全量注入
- F6: 缓存命中验证 —— 解析 DeepSeek usage 的缓存字段（`prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`，真机确认字段名），会话内显示缓存命中率；结构化前后对同一任务做人工对比（响应速度 / token 费用），记录到评估文档

## 非功能需求

- N1: 缓存前缀稳定性 —— 每轮请求的稳定前缀（主 system 消息 + 工具描述）逐字节一致，不得混入轮次变化内容
- N2: 模块可插拔 —— 新增/删除模块只改模块注册表，不触碰拼装逻辑
- N3: P3 兼容 —— /plan /do 的模式指令走轮次注入机制，功能不回退
- N4: 缓存语义不变 —— 双 system 消息不改变模型对话行为（无回归）

## 不做的事

- 项目指令文件加载（AGENTS.md / CLAUDE.md 读取）
- 自动记忆与长期记忆实现（仅留模块位）
- 真实 MCP 接入
- 自动化评估系统

## 验收标准

- AC1: 模块拼装正确 —— 七个模块按优先级顺序、空行分隔、环境信息最后；模块注册表增删模块生效
- AC2: 前缀稳定 —— fake 断言：连续两轮请求的主 system 消息字节完全一致
- AC3: 环境分流 —— 环境信息在独立 system 消息中，主 system 消息不含 cwd/日期
- AC4: 双重强化 —— 至少 2 条关键规则同时存在于工具描述与系统提示
- AC5: 轮次注入 —— fake 断言：第 1/4/7 轮全量注入、第 2/3 轮精简注入、切换模式立即全量
- AC6: 缓存验证 —— 真机 usage 含缓存字段时显示命中率；评估文档记录结构化前后对比
- AC7: 回归 —— P3 全部测试通过，/plan /do 行为不变
